# 🤖 Agentic Vision · 智能体视觉

> 一句话：**视觉从"看一眼"变成"动起来看"。**
> 模型不再被动接收一张图，而是主动决定看哪里、放大多少、调什么工具、何时回头验证——感知本身成为行动。

## 1. 与传统 VQA 的分水岭

| 维度 | 传统 VQA / VLM | Agentic Vision |
| :-- | :-- | :-- |
| 输入 | 一次性给全 | 按需获取（截图流、裁切、检索结果） |
| 交互轮次 | 单轮 | 多轮，状态跨轮累积 |
| 动作空间 | 只有"输出答案" | 输出动作：点击/滚动/裁切/调用工具/检索 |
| 失败模式 | 答错 | 走错路、循环、丢状态、误点 |
| 评测 | 准确率 | 任务成功率 + 步数 + 成本 |

## 2. 动作空间：视觉 agent 到底能"做"什么

```
                     ┌─ 注意类：crop / zoom / 高分辨率重采样 / 选帧
   视觉动作 ──────────┼─ 标注类：画框、打点、涂掩码、把图当草稿纸
                     ├─ 检索类：以图搜图、视觉 RAG、跨帧检索
                     └─ 环境类：点击、拖拽、键入（GUI）、移动（具身）
```

**关键洞察**：注意类与标注类动作，本质上是把"隐式推理"外化成"可检查的视觉操作"。这也是 latent visual reasoning 与 agentic vision 的天然接口——一个在内部想，一个在外部做。

## 3. 四条主要子线

| 子线 | 场景 | 核心难点 | 典型能力要求 |
| :-- | :-- | :-- | :-- |
| **GUI / Computer-use** | 操作桌面与网页 | 元素定位（grounding）、坐标精度、长任务状态跟踪 | 截图理解、OCR、坐标回归、动作历史建模 |
| **视觉搜索 agent** | 多跳视觉问答 | 何时检索、检索什么、如何融合多张证据图 | 查询改写、证据选择、冲突消解 |
| **图像工具编排** | 图像编辑/科学图表分析 | 工具选择与参数化、编辑后自检 | 工具 schema 理解、结果验证 |
| **具身视觉导航** | 机器人/室内导航 | 部分可观测、实时性 | 主动探索、空间记忆 |

## 4. 训练范式

- **轨迹蒸馏**：采集人类操作轨迹做 SFT，成本低但泛化差、易学成"模仿而非理解"。
- **可验证奖励 RL**：以任务是否完成为奖励（GUI 任务可用最终状态校验），是当前主流。
- **在线自博弈 / 探索**：让 agent 在沙箱里自己试，靠环境反馈学习恢复策略。
- **数据合成**：从网页/应用自动生成任务与标注（元素级 grounding 标注最贵）。

> 读这类论文时先问三件事：**任务从哪来？奖励怎么给？失败样本怎么处理？** 大部分性能差异来自这三点，而不是模型结构。

## 7. 常用评测

| 基准 | 测什么 | 备注 |
| :-- | :-- | :-- |
| `OSWorld` | 真实操作系统任务 | 端到端成功率，最接近实用场景 |
| `ScreenSpot` / `ScreenSpot-Pro` | GUI 元素定位 | 高分辨率专业软件是重灾区 |
| `WebArena` / `Mind2Web` | 网页任务 | 可复现的沙箱环境 |
| `VisualWebBench` | 网页理解多任务 | 偏感知而非操作 |
| `AndroidWorld` | 移动端操作 | 动态环境，鲁棒性考验 |

## 8. 开放问题

- 视觉 agent 的**状态表示**：全量截图历史 vs 压缩记忆 vs 结构化状态树？
- 什么时候该"动手"（裁切/点击），什么时候该"再想"？动作与思考的预算如何分配？
- 长任务的错误累积：单步 95% 正确率，20 步后只剩 36%——如何做过程级纠错？
- 高分辨率与成本的两难：ScreenSpot-Pro 类任务必须放大，但放大就爆 token。
