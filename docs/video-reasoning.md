# 🎬 Video Reasoning · 视频推理

> 一句话：**从"视频问答"升级为"在时间里做推理"。**
> 因果链、事件先后、跨帧指代、长程记忆——视频推理的难点从来不是"看见"，而是"在有限 token 里记住足够长的时间"。

## 1. 为什么视频比图像难一个量级

| 挑战 | 图像 | 视频 |
| :-- | :-- | :-- |
| token 量 | 一张图 ~ 数百 token | 1 分钟 30fps ≈ 1800 帧，全采样不可行 |
| 信息密度 | 高，全帧都是证据 | 极低，多数帧是冗余 |
| 时间结构 | 无 | 因果、先后、持续、重复、突变 |
| 证据位置 | 一次性可见 | 关键帧可能在任何位置，且只出现几帧 |
| 在线场景 | 无 | 流式输入，无法回看未来 |

**结论**：视频推理的本质是**一个信息检索 + 压缩问题**，而不是单纯把上下文拉长。

## 2. 四种应对策略

```
① 稀疏采样          均匀/关键帧采样，便宜但可能漏掉短事件
② 压缩记忆          把长视频压成固定预算的 memory（token merge / 摘要 / KV 压缩）
③ 检索式            先建索引，按问题检索相关片段（视觉 RAG）
④ 主动式            模型自己决定看哪段、看几帧（video agent，与 agentic vision 交叉）
```

| 策略 | 优点 | 代价 | 适用 |
| :-- | :-- | :-- | :-- |
| 稀疏采样 | 实现最简单 | 短事件召回差 | 短视频、粗粒度问答 |
| 压缩记忆 | 上下文可控 | 压缩过程不可逆，细节丢失 | 长视频摘要、整体理解 |
| 检索式 | 长视频可扩展 | 依赖索引质量与查询改写 | 定位型问题（"第几分钟发生了什么"） |
| 主动式 | 精度最高 | 推理成本高、延迟大 | 高价值长视频分析 |

## 3. 任务谱系（按难度递增）

1. **描述/摘要**：发生了什么
2. **时序定位**：什么时候发生、持续多久
3. **跨帧指代**：那个"它"指的是谁
4. **因果与反事实**：为什么会这样、如果不这样会怎样
5. **长程计数与状态跟踪**：数次数、跟踪物体状态变化
6. **流式在线决策**：边看边判断（自动驾驶、监控告警）

## 4. 与 latent / agentic 的交叉点

- **视频 latent**：把整段视频压成少量 latent 状态再做推理，与 latent visual reasoning 的"隐视觉派"同源。
- **视频 agent**：主动选帧、主动回看、主动调检索工具，是 agentic vision 在时间轴上的展开。
- **共同瓶颈**：token 预算。所以本仓库单列了 [视觉推理效率](efficient-visual-reasoning.md) 这一横切赛道。

## 7. 常用评测

| 基准 | 侧重 | 备注 |
| :-- | :-- | :-- |
| `Video-MME` | 综合长视频理解 | 分短/中/长三档，看衰减曲线 |
| `LongVideoBench` | 长上下文指代推理 | 强调"针在草堆里" |
| `MVBench` | 时序任务集合 | 20 类细粒度时序能力 |
| `TempCompass` | 时序敏感性 | 专门测"是否真的在看顺序" |
| `Video-MMMU` | 视频中的知识获取 | 学科知识 + 视频 |
| `EgoSchema` | 第一视角长视频 | 需长程因果 |

> 常见坑：只报平均分。务必看**时长分档曲线**——很多方法在短视频上很强，超过 10 分钟就崩。

## 8. 开放问题

- 压缩到什么程度是极限？是否存在"信息论下界"式的分析？
- 流式场景下的"遗忘"策略：什么该记住、什么可以丢？
- 视频推理的忠实性：模型给出的时间戳是真在推理，还是碰巧对齐？
- 多视频/跨视频推理（对比两段视频的差异）几乎还没被认真做。
